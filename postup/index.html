Jak vznikl EPOX web

Celý postup krok za krokem: co jsi chtěl ty, co jsem udělal já a proč, jaké problémy se objevily a jak jsem je vyřešil. Dole je kompletní kód s vysvětlením.

🌐 EPOX web 📁 Kód na GitHubu ✅ W3C HTML ✅ W3C CSS
Jak pracuji Časová osa Nastavení a nástroje Commity Kód Slovníček

01Jak pracuji

Tenhle cyklus se opakoval u každé změny webu.

ZadáníPřečtu, co chceš. Když je něco nejasné, zeptám se dřív, než začnu psát.
Psaní kóduNapíšu soubory index.html, style.css a script.js ve svém pracovním prostoru.
TestZkontroluju syntaxi (node --check) a otevřu web v neviditelném prohlížeči Chromium, kde proklikám tlačítka a hledám chyby.
Přenos k toběZkopíruju hotové soubory do složky Dokumenty\EPOX-web na tvém počítači.
Git commitUložím změnu do historie gitu se zprávou, co se změnilo.
Git pushPošlu změny na GitHub přes git na tvém počítači, kde jsi přihlášený.
OvěřeníPočkám, až GitHub Pages web postaví, otevřu ho a nechám ho zkontrolovat W3C validátory.

02Časová osa

Zelená tečka = krok práce, žlutá = problém a jeho řešení.

  1. 14:55

    Zadání

    Chtěl jsi web se 3 tlačítky dole: „co jsme dělali“, kontrola kódu a kontrola v jazyce, který se dá naučit za 60 sekund. Obsah klidně náhodný, klidně s cmd. Nahrát na GitHub do repozitáře EPOX.

  2. 14:56

    4 otázky

    Zeptal jsem se na jazyk (vybral jsi Markdown), co má kontrola dělat (web zkontroluje sám sebe), jak se to nahraje a co má být v historii. Upřesnil jsi, že tohle je EPOX web, oddělený od EPOX softwaru.

    Proč: špatný odhad u věcí, které se těžko předělávají, stojí víc než jedna otázka.

  3. 14:58

    Napsal jsem 4 soubory

    index.html (kostra), style.css (vzhled), script.js (terminál s 15 příkazy, karty, 3 tlačítka, kontrola kódu, převod do Markdownu) a README.md (popis pro GitHub).

    Proč 3 soubory místo jednoho: HTML, CSS a JS mají každý svou roli, takže se v nich líp vyznáš a W3C validátor umí CSS zkontrolovat zvlášť.

  4. 15:01

    Test v prohlížeči oprava

    Spustil jsem web v neviditelném Chromiu, napsal do terminálu help, vtip, color a neexistující příkaz a proklikal všechna tlačítka. Žádná chyba v JavaScriptu. Text ale tvrdil „16 testů“ a ve skutečnosti jich bylo 18, tak jsem to opravil.

  5. 15:08

    Přesun na tvůj počítač

    Byl jsi na jiném počítači, jen s diskem C:. Požádal jsem o přístup ke složce Dokumenty a vytvořil v ní EPOX-web. Z webu jsem smazal všechny zmínky o EPOX softwaru.

  6. 15:10

    Git na tvém počítači povolení

    git init, git commit a připojení repozitáře origin. Git si při práci maže vlastní pomocné soubory .lock, a k tomu jsem potřeboval tvé povolení mazat ve složce Dokumenty. Nic jiného jsem nesmazal.

  7. 15:11

    Push na GitHub

    Push jsem spustil přes git na tvém Windows, kde jsi přihlášený do GitHubu. Heslo jsem nikdy neviděl ani nezadával.

  8. 15:14

    404 – repozitář byl soukromý problém

    GitHub Pages zadarmo funguje jen pro veřejné (public) repozitáře. Přepnul jsi repozitář na public.

  9. 15:25

    GitHub Pages bylo vypnuté problém

    Přihlásil ses v prohlížeči v aplikaci a já jsem v Settings → Pages nastavil main / (root) a dal Save. Po minutě web běžel: 18× OK.

  10. 15:33

    Oficiální W3C validátory

    Do kontroly jsem zapojil validator.w3.org (HTML) a jigsaw.w3.org (CSS). Web se jich ptá přes fetch() a čte odpověď ve formátu JSON.

  11. 15:40

    Prohlížeč ukazoval starou verzi cache

    Prohlížeč si pamatoval starý script.js. Řešení: v index.html píšu script.js?v=3. Když se číslo změní, prohlížeč soubor stáhne znovu.

  12. 15:45

    2 varování z CSS validátoru oprava

    word-break: break-word je zastaralé, nahradil jsem ho moderním overflow-wrap: anywhere. Výsledek: 20× OK, 0 varování, 0 chyb.

  13. 15:55

    Tlačítka → oficiální weby, tahle stránka na Vercelu teď

    Tlačítko Kontrola kódu otevře W3C HTML validátor, Kontrola v Markdownu otevře W3C CSS validátor. Vlastní kontrola zůstala v terminálu (příkazy kontrola a md). K tomu vznikla tahle stránka.

06Slovníček

Pojmy, které se v postupu objevily.

PojemCo to je
gitProgram, který si pamatuje historii souborů. Každá uložená verze je commit.
commitUložená změna se zprávou, co se změnilo.
pushOdeslání commitů z počítače na GitHub.
repozitářSložka projektu na GitHubu včetně celé historie.
GitHub PagesSlužba GitHubu, která ze souborů v repozitáři udělá web na adrese …github.io.
VercelJiná služba pro hostování webů. Tahle stránka běží na ní a sama se aktualizuje po každém pushi.
W3COrganizace, která určuje standardy webu (HTML, CSS) a provozuje oficiální validátory.
validátorProgram, který zkontroluje, že kód odpovídá standardu.
fetch()Funkce JavaScriptu, která stáhne data z jiné adresy, třeba výsledek validátoru.
cachePaměť prohlížeče. Ukládá soubory, aby se web načítal rychleji, ale umí ukazovat starou verzi.
MarkdownJednoduchý jazyk na formátování textu: # nadpis, - seznam, **tučně**.
